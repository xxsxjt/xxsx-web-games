# 阶段 11：停泊最终 tick 的耗尽/超时优先级

日期：2026-11-20。仅增加测试与回归注册，不改生产物理、地图、损伤、资源消耗或结算顺序。

## 测试方法与限制

- `tests/terminal_priority_fixture.gd` 在每个合同的港内设置已挂索双体、零初速度与松弛拖缆。先由正常 `Sim.step()` 或应用 `_advance_simulation()` 连续运行 59 个 1/60 秒步长，实际取得 0.983333 停泊进度；不直接写入 `dock`、成功状态或报告。
- 第 60 tick 前只设定待验证的剩余资源/任务时钟。耐久用例在合同的深副本添加半径 0.5 m 的测试礁石，以真实连续擦碰分别损伤船体或舱体。双体在碰撞推离后仍需符合正式港圈、速度和张力规则。
- 初轮夹具把船体 1.55 m 安全余量用于舱体，导致舱体没有接触，定向断言正确失败。修正为舱体自身 1.10 m 余量后重测通过；未通过修改生产规则迎合测试。
- 两个正式合同的礁流列表保持不变。该用例是合成的终局顺序边界，不表示正式港内有这些礁石，不是从开局自然驾驶返港，也不替代阶段 10 的实际路线或未来真人试玩。

## 每合同 14 档对照

| 类别 | 最后 tick 条件 | 预期结果 |
|---|---|---|
| 基线 | 资源充足、期限前 | 正常成功并生成报告 |
| 电量正余量 | 本 tick 消耗后仍余 0.001 | 正常成功 |
| 电量恰好耗尽/不足 | 等于/少于本 tick 实际消耗 | `power_lost` 失败 |
| 船体擦碰 | 初始耐久 1 / 0.05 | 分别成功 / `collision` 失败 |
| 舱体擦碰 | 初始完整度 1 / 0.05 | 分别成功 / `collision` 失败 |
| 时间边界 | 最后 tick 在期限前 / 恰好到达 / 跨过期限 | 分别成功 / `timeout` / `timeout` |
| 电量与时间同时耗尽 | 同 tick 电量归零并超时 | 保留电量耗尽原因 |
| 舱体、电量、时间同时耗尽 | 同 tick 舱体与电量归零并超时 | 保留舱体破损原因 |
| 全部同时耗尽 | 船体、舱体、电量归零并超时 | 保留船体归零原因 |

所有失败都保持停泊进度 0.983333、不产生成功报告；终态后再输入不会推进模型。以上优先级是现有正式逻辑的验证结果，不是新设定。
