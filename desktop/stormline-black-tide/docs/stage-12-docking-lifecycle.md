# 阶段 12：临港暂停/失焦、恢复与重开一致性

日期：2026-11-20。仅新增 headless 应用测试、QA 注册和说明，不改生产控制、物理、音效、存档或结算规则。

## 场景与覆盖

`tests/docking_lifecycle_test.gd` 复用阶段 11 的港内双体夹具，但不添加礁石。每合同先经应用 `_advance_simulation()` 真实取得 59 tick 停泊，再完成第 60 tick 并保存独立测试成绩，之后执行下表 10 档，两个合同共 20 档。

| 暂停入口 | 退出方式 / 边界 | 判定 |
|---|---|---|
| 合成 P / 失焦回调 | Esc 恢复，资源充足 | 快照不变地恢复，再一个正常 tick 成功 |
| 合成 P / 失焦回调 | Esc 恢复，电量恰好只够最后 tick 消耗 | 正常耗尽失败，不伪造成停泊成功 |
| 合成 P / 失焦回调 | Esc 恢复，最后 tick 恰好到期限 | 正常超时失败，不补算成功 |
| 合成 P / 失焦回调 | R 重开 | 新任务时间/停泊清零，未扫描/未挂索，无旧报告或排队输入 |
| 合成 P / 失焦回调 | Enter 回任务台，再 Enter 开航 | 正常清空旧任务并开新局，首 tick 不继承停泊 |

每档均检查：

- 暂停前从应用键盘适配器排队一次 Space；进入暂停立即清除，暂停时 Space 不会排入延迟挂索。
- 重复两次失焦回调不会把暂停误切换为继续。
- 在暂停时分别传入 1/60、0.75、60 秒更新，调用应用模拟边界、物理回调和呈现回调，整份模型快照保持完全一致：时间、位置、速度、资源、停泊、事件和报告都不变化。
- 暂停/恢复/失败/重开不改已保存的最佳文件字节及重读排名；成功恢复只得到现有最佳提示，失败提示为空。
- 恢复后结算只增加一个 1/60 秒模拟步长；debrief 后失焦或大 delta 不会重放结果。

**定向结果：335 项断言、0 失败。** 完整 QA 新增 `docking_lifecycle`，由 14 项扩展为 15 项；阶段 11 的 693 项终局优先级、阶段 10 的 69/28 项恢复套件继续保留。
