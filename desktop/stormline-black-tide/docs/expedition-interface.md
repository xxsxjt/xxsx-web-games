# 远征应用与船坞界面

## 实施计划（2026-11-21）

1. 在原任务台加独立的远征入口，保留三张快玩卡、键盘 1–3、原成绩与复盘。`main` 继续是唯一场景组合、输入和页面生命周期入口，远征档路径单独导出、测试注入；任务台和远征档案页只读，不启动即创建/恢复档案。
2. 新增原生船坞面板：持久资源、三海区六节点航图、当前候选合同的可比较实参、改装槽位和载荷、维修/充电及账本。只从 State/Catalog 获得规则数据；选择合同不写磁盘，确认出航才提交保存。长内容用可滚动容器，主导航和确认按钮不藏在滚动末尾，支持鼠标或 Tab / Enter。
3. `act → save → reset_expedition → running`；旧世界从 `sim.contract` 配置，驾驶台、雷达与世界从同一个快照显示。真实终态才调用 `settle`，快速合同仍走原成绩存储。结算一旦计算即冻结候选，写盘失败只重试同一个版本，不再次结算或诚称已入账；陈旧档不覆盖。
4. 原快玩 R 不变；远征 R 不重启，暂停只能继续或确认按中断规则放弃。退出请求不得跳回出航前；重新加载 active 显示其事由，按 State 的恢复规则入账并保存才继续。终局可明示另起远征；坏主档只能明确恢复有效备份，或由玩家保留/处理原文件后重查。
5. 无窗口应用回归：真实场景、按钮和按键、只读旧 Pilot 给 `_advance_simulation` 合法输入。至少一条完整六部署和另一构筑的首部署，通过独立 `.testdata` 档验证带伤、维修/充电、失败/放弃/中断、保存失败/陈旧写冲突、重载与终局。冻结前做四个视口 Control 几何、定向旧应用/驾驶台回归、UTF-8 与 SHA-256 检查；不运行共享总 QA、图形客户端或更改工作树之外的源码。

## 玩家怎样完成远征

1. 在原任务台按 **X** 或点「远征 / 继续远征」。档案页只读；首次需选「新建远征」，有档则继续或看终局。旧三张快玩合同仍用卡片或 **1–3** 选择、**Enter** 开航，快玩可按 **R** 重开，成绩与远征无关。
2. 在「航图与合同」看黑潮水域 → 针礁水道 → 碎潮回廊。每区先选勘测或打捞，再做主回收，最后回收旗舰核心；每个节点都可选保守或冒险。勘测为后续回收换来更宽的窗口、更轻的舱和较弱的风暴，打捞现在多赚资金与材料，但后续条件更紧。卡片比较海况基准、舱重、时限、航费、报酬上限和材料；海况基准不是航行中固定的实时风暴。
3. 「船厂整备」显示持久资金、材料、船体、余电、压力和实际的两槽 / 三负载上限。先购买再安装；增压推进器多耗电、稳索配重架加重船体、脉冲声纳锁定更快但更耗电，两个重模块不能同装。维修耗 14 资金和 1 材料、最多回 25 点船体；充电耗 10 资金、最多回 40 点电量；两者均使压力 +1（到档案上限为止）。可带伤出航，但至少要有 20% 船体、25% 电量和航费；最低门槛并不保证有足够返航余量。
4. 「确认出航…」预览真实报价、扣费与出航配置，**Esc** 可取消。进入原 3D 海域后，**W/S、A/D** 或方向键驾驶，**1/2/3** 切动力档，**E** 长按扫描，**Space** 挂索，**Shift** 慢车，**Q/F** 收／放缆。驾驶台报出动态合同、余时、有效构筑参数和真实门槛；先扫描再挂索，返港时船舱都要在圈内、速度 ≤2.6 m/s、缆张 <额定的 68%，连续保持 1 秒。
5. **P/Esc** 暂停或继续，失焦也会暂停；远征禁用 **R**。终态显示结果与是否已入账，**V** 或复盘按钮切换旧版采集口径的航次摘要（不是逐帧回放，也不是完整碰撞统计）。回船坞整备、看持久账本，再出航；也可确认撤退。终局不暗中重开：「另起远征」才写入全新档案，上一份终局进入轮换 `.bak`。

非驾驶页面可用 **Tab / Enter**、滚轮或 **PgUp/PgDn/Home/End**；状态与主要按钮固定，长报价、账本和复盘在原生滚动区。确认页默认焦点为「取消」。

## 写入与恢复契约

| 情形 | 界面行为与记账规则 |
| --- | --- |
| 出航或整备写失败 | `main` 从 State 计算候选，经 Store 保存并读回验证才提交到场景；出航未保存则不重置模拟、不起航。选择报价、打开或取消确认不写档。 |
| 航次真实成功／失败 | 通过部署令牌和任务身份结算一次。成功按舱完整度给资金，发交付材料并解锁下一节点；失败不给报酬，保留真实损耗、另扣 8 点船体、压力最多 +2，已完成节点不倒退。始终不调用旧快玩成绩写入。 |
| 结果未保存／档案冲突 | 停在暂停或结算页，显示「尚未入账」。写入故障解除后可重试同一份候选和原修订；档案另有新字节时只有确认舍弃本机结果并重读，不能重复结算、覆盖或合并。退出未保存结果需另行确认。 |
| 当场放弃／正常关闭游戏 | 先暂停，确认后按**当前实测**船体与余电再扣 15/20 点、压力最多 +2；不退费、不奖励、不推进节点。暂停页区分「出航」登记和「当前」真实资源。 |
| 重载 active 档，没有末帧 | 不能接着开船。明示按**出航登记**扣同样 15/20 点，只有存回档案才返船坞。不会假称恢复最后一帧，也不保证故意杀进程后仍保留途中损耗。 |
| 坏主档 | 有合法备份才显示恢复，恢复要确认、保留原坏字节（`.corrupt-*`）；无可用备份时禁止新建覆盖，提示先在游戏外处理并重查。有效主档不会自动回滚。 |

正式档路径由 `main.expedition_file` 注入，默认 `user://stormline-expedition-v1.json`。State/Catalog 是船坞唯一规则来源；`launch → Store → launch_spec → reset_expedition` 后，`world.configure(sim.contract)` 和 HUD/雷达使用同一部署、同一快照。模块影响动力、能耗、声纳和拖缆额定，不改变共同的扫描、挂索或入港门槛；驾驶提示直接引用 StormSim 门槛常量，而不是再维护一套比较式。

- **七次都有船舱均入圈并稳定 60 tick 的真实交付，也都读回了持久结算。** 完整远征有七次付费充电，在第三次交付后重建正式场景读回继续；买下第三模块后实证「有空槽」仍不能同时装两个重模块。六节点均标已交付，终局重载后仍可查看；明确另起保留上一份终局备份。另一支线实证同压力下给下一回收带来更强的海况、更重的舱和更短的窗口。
- 另一构筑在第二部署实际用声纳耗电并碰礁，40.13 秒主动放弃：船体 **78.72 → 63.72**，电量 **73.04 → 53.04**，不退款也不推进。花 14 资金和 1 材料修到 88.72，再花 10 资金充到 93.04，带伤实航；自然超时 **137.00 秒**，无奖励，随后明确撤退。独立中断场景消费过资源后卸载正式场景，重载只凭真实出航档返港 **100 → 85** 船体、**100 → 80** 电量，不继续驾驶。
- 单独阻挡 `.bak` 更新，实证无法免费启动、已物理交付也不能先入账、解阻后只入账一次；中断救援也必须先保存。两个正式场景顺序交错写同一夹具，验证陈旧出航不扣费和陈旧结算不发奖。后者的物理成功（**76.93 秒**）因另一场景已救援返港而被拒，磁盘进度保持 0，**不计作第八次交付**。坏主档无备份时只可重查，有备份时明确确认恢复且逐字节保留原坏档。
- 旧三合同卡片及 1–3/Enter、快玩 R、暂停、V 复盘及投影仍通；一条实际快玩交付也不降级预置的更优成绩。成绩主档、`.bak`、碎潮 sidecar 和备份四份夹具在读回点与预置字节一致。整备及成功结算的纯规则结果与 JSON 读回对照中，只有浮点船体/电量允许 `1e-9` 差异；标识、修订号、资金和材料精确比较，重复结算及冲突则另外比较主档原始字节。
- **960×600、1280×720、1440×900、1920×1080** 原生 Control 几何：档案、六节点与报价、整备、确认、驾驶台和真实双体入港、暂停、待保存、正反终态复盘、终局账本、撤退及故障页；检查可见面板边界、固定按钮、字体和焦点样式、焦点随滚动可达及最后一行可达。
