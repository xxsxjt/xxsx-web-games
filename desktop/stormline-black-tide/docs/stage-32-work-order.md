# 阶段 32：可撤销的船厂整备工单

日期：2026-11-26；源码 v0.2.6。目标是把跨航次维修、充电、材料和改装取舍做成可先比较再提交的实际玩家操作，不增加合同／部署或另建模拟与档案系统。最终双侧验证与同步回执存本机 `build/sync/stage-32-evidence-index.json`，未完成回执前不声称同步完成。

## 玩家闭环与兼容

- 原船坞新增「整备工单」页。最多12项原服务／模块／封堵包操作，按顺序用实际资金、材料、拥有模块和负载规则投影；可撤销末项、清空和取消确认。显示资金、材料、压力、船体、电量、装备、结构破口／包数及所选合同实参前后对照与付航费后余额。购买和安装仍为两步，维修和充电仍推进压力；不是最优配置或返港保证。
- 草案只在内存。出航和即时整备须先提交或清空；返回任务台／正常退出确认舍弃。写失败保留未付费草案，陈旧冲突不能覆盖、合并或部分提交，明确重读会丢弃草案。
- 纯规则 `preview_work_order` 调用同一个 `act`，不复制价格、压力、负载、模块或修理公式；最终 `work_order` 只允许七种既有船坞操作，拒绝 launch／settle／restart／升级损管等动作。最终一次 revision +1 / Store 保存，原各项 history 事件与24条上限保留。没有持久工单字段或新事件名；老 v1 读取／身份／路径不变，旧远征不自动启用损管。
- Sim、Catalog、Damage、Store、快玩三合同、最佳记录／sidecar 和网页源码保持原字节。仍使用原 launch_spec → 同一个 Sim → 公开 snapshot → State settle → Store 路径；备航配置不旁路实际驾驶。

定向规则覆盖顺序资金／材料、整单拒绝、只读投影、修订上限、history 上限、旧／损管形状、舱坞限制；应用用正式按钮与隔离 Store 覆盖撤销／清空／取消、写失败／冲突、重载、一次提交、旧档兼容和付费出航。真实第一部署用既有输入 Pilot 扫描、挂索、拖回与双体连续60 tick停泊，再用真实剩余资源做第二部署整备／压力预览与持久提交。无位置、HP、电量、奖励或终态注入；纯规则合成夹具单独标识。
