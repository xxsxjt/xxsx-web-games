# V51：独立总站与第一轮质量升级

日期：2026-10-07。实现基线：原站点 V50 与 GitHub 规划提交 `31d3b8a907fbceff2a0a3d98cad34b5c510a68f1`。

## 本轮完成

- **独立总站**：首页直接展示六款游戏，用当前界面截图作封面，提供类型筛选、收藏、最近打开和明确的操作与存档说明。名称暂用「XXSX 游戏站」，不要求未来作品加入舰站世界观。六款游戏都标注测试版。
- **按入口加载**：总站只请求自己的 HTML、CSS、JS、目录和封面。游戏进入 `play.html` 后加载公共模块与对应玩法模块；战术和解谜入口不提前加载射击美术。旧 `#game/*`、`#station/*` 书签转到相应页面，返回按钮回到总站。
- **射击战役闭环**：默认战役在第十波终局 Boss 击破后胜利结算；无尽模式继续推进，拥有独立最高分与波次纪录。通关、战机损毁和主动结束分别记录结果。胜利后可开启一局新的无尽挑战。
- **结算与兼容修正**：防止最后 Boss 升级状态遮挡胜利、重复结算及结算后继续计分。无进度退出不发星尘或舰站物资。旧总最高分与波次保留，新模式纪录单独计算。越界冲击在无敌期内给出准确提示。
- **发布基础**：生成带内容哈希的入口资源与 `release-manifest.json`，校验源文件及发布文件内容。保留一轮旧资源 URL 别名，兼容缓存的 V50 页面。构建和测试只依赖 Node 内置模块；开发预览优先 Vite，缺少依赖时用内置静态服务。

## 实际验证

构建完成后运行 `npm test`，退出码 0，输出 198 个 PASS/✓，无 FAIL。这个数字代表检查输出，不代表 198 次完整游玩。新增检查覆盖战役终局、无尽继续、一次性结算、退出奖励、旧纪录保留及无敌期冲击提示；保留了战术存档与损坏恢复等原有回归检查。

浏览器预览检查了六个游戏的开局与返回总站、收藏筛选及刷新持久化、旧 `#station/signals` 书签转入信号中继。检查了正式 `dist/` 首页的六张封面和哈希脚本加载，并实际进入战役、退出至结果页，确认零进度退出显示星尘 +0。战术入口的 DOM 脚本只包含公共模块、战术模块与适配层；DOM 图片没有请求射击美术。

总站在同源 iframe 的 320、375、414、768px 宽度下检查了六卡片及控件边界；实际内容宽度扣除滚动条后分别为 305、360、399、753px，无横向溢出。320px 下将根字体放大到 200% 后也重新检查了控件边界。这是布局检查，不等同于真实手机的触控、DPR 或系统缩放测试。

## 仍需完成

这一轮完成产品结构与结果状态的基础，不代表整个升级规划交付完毕：

- `src/game.js` 仍是较大的共享适配层；尚未把各游戏彻底分成独立生命周期模块。
- 五段航线、装备和 Boss 的原有机制继续使用，尚未完成规划中的三种清晰构筑路线、Boss 全面重做和新的平衡调整。
- 战术与电路解谜的深度内容、美术、触控与无障碍升级仍按总规划推进。
- 云浏览器出现长帧保护暂停，不能据此判断手机帧率；没有真实手机 FPS、加载时间、LCP 或实际十波通关的测量结果。
- 射击美术资源仍较大，未达到规划中的完整资源预算。浏览器局内刷新续玩仍仅对支持它的战术游戏提供；射击和短局游戏如实标明不支持。

下一轮优先对射击核心操作、三种构筑路线和 Boss 预警做实玩迭代，再推进战术与解谜的完成度；新增游戏排在这些质量改造之后。完整目标与验收要求见 [总站与游戏质量升级规划](quality-upgrade-plan-2026-10-07.md)。
