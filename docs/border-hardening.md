# 《边境战术》行动说明与拒绝反馈加固

日期：2026-11-21。切片仅修改 `src/border.js`，新增 `tests/border-hardening.cjs` 与本文；共享配置、页面、样式、旧测试、存档键、规则版本及发布产物均不在写入范围。

## 目标与已核查缺口

- 保留 ruleset 2 战术循环、地图、敌方 AI、数值与自然通关策略；无 `ruleset` 字段的进行中档案继续按旧规则运行。
- 原页面只有射击显示预估，技能自动目标、治疗对象、推击落点/撞击及 AP 后果不够明确，且目标锁定没有取消入口。
- 确定性反馈缺陷：0 AP 点击本可达格会被告知“该格不可达”；冷却中的医护兵会被告知“附近没有需要治疗的队员”；最终撤离提示错误依赖已经包含抵达撤离格的 `sectorClear`，因而需要移动时不显示；技能打断后旧预警仍标红。
- 统一只读行动检查供真实动作、按钮可用性、格位说明及可测 view 共同使用，避免另建预测规则。

## 执行与验收计划

1. **完成**：先新增失败复现及基于真实动作/view 的确定性测试，首次运行明确复现错误文案、撤离提示缺失、打断后红标滞留、死亡目标残留及冲突提示被覆盖。
2. **完成**：在独占模块内实现规则共用、准确拒绝、目标取消和动作前后反馈。
3. **完成**：原归档测试、原 110 动作自然旅程、新增 hardening 测试及语法检查通过。
4. **冻结交回**：由集成人员负责根配置、构建、dist 和 Git；本切片不代做。

## 玩家可见变化

- 选敌后，同时显示射击、当前技能及推击的实际合法性、AP 代价和确定后果。技能按钮直接显示自动/锁定目标对应的名字、伤害或实际治疗量；不再需要按下技能才知道会治疗谁。
- 移动格说明含真实寻路步数、目标坐标、1 AP 与剩余 AP、进入掩体/预警区/泄压区提示。以既有格位 `title` 和 `aria-label` 提供，不新增点击确认步骤、不改移动节奏。
- 推击区分合法位移与受阻撞击，显示目的地、12 点撞击伤害、当前警戒射击链、最终 HP 与打断状态；不把所有推击都写成固定伤害。
- 成功动作在战术提示中保留一条“已执行”回执，包含实际目标、确定效果和 AP 余量；切换干员/目标、结束回合、选择补给或重开会清理旧回执。
- 连续点击当前敌人（敌人卡或棋盘都可）取消锁定；取消只影响选择，不耗 AP、不主动写档，下一次攻击技能恢复原有自动选敌。选择干员后首次重新点选已有目标仍是幂等确认，第二次才取消，保留现有“选干员→选目标→动作”的操作及自然回放。
- 锁定目标被击毁时清除过期锁定，下一技能不再被一个已死亡目标堵住；目标仍存活但超射程时不会偷偷改打另一个敌人。
- 0 AP、冷却、射程、墙体、相邻距离、指挥机免推、终端占格、路径不可达、阶段等拒绝原因来自真实动作共用检查，明确写“未消耗 AP”。
- 技能/推击打断后，棋盘红标及敌人卡立即按 `staggered` 显示失去下一次行动，不再继续展示已被取消的攻击威胁；不改写原 intent 或 AI。
- 敌人与终端处理完但尚未撤离时，明确提示“任意存活干员”到 ⇧，不错误要求全队撤离。跨页档案冲突警告在有锁定敌人时也不会被射击预估覆盖。

## 共用规则与兼容边界

`debug.inspectAction(state, unitId, kind, target?)` 是只读行动计划；`debug.getActionView(state, unitId)` 对当前锁定生成射击、技能、推击、警戒、掩护、启动终端的组合 view。返回 `ok`、拒绝 `code/reason`、`summary`、`cost/requiredCost/apAfter`，合法动作按需携带路径、位移、目标、伤害/治疗量、剩余 HP、冷却及打断结果。真正动作先取得该计划再执行，UI 不另写距离、冷却、伤害或治疗排序公式。

- 真实动作仍使用现有 `attackDamage`、`findPath`、`targetOptions` 和状态迁移。推击与敌人移动警戒共用 `overwatchShots`，保持小队顺序、掩体/交叉火力修正及击杀后停止射击。
- view 不执行敌方回合、不抽随机数、不复制执行整场战斗、不写日志/分数/存档；`path` 和反应列表是新建数据，不向外暴露可写的状态对象。
- `performAttack(..., true)` 原有兼容入口仍按其原武器射程/伤害行为运行；页面技能继续用 `useAbility`，工程师技能仍为 5 格、普通武器仍为 4 格。
- 无 `ruleset` 字段的旧进行中档案不迁移、不补版本：移动仍加 2 分、远距射击不套 ruleset 2 掩体折减、反应堆不增加 ruleset 2 泄压。新局仍是 ruleset 2；存档键仍为 `neonBorderTacticsSaveV1`，schema 未变。
- 警戒按钮现在与原本已经允许的真实 `setOverwatch` 合法性一致，不再独自增加“场上必须有敌人”的 UI 特例；没有新增或改变警戒消耗/伤害/时机。
