# 余烬航团 / Ember Convoy

三段、两条航路、三种舰船分工。完整闭环为选航路 → 交战 → 打捞 →（前两段）改装 → 最终确认撤离；败局与胜局都可使用同一种子重开。源码入口 `games/ember-convoy.html`，不依赖旧游戏适配层。

## 草稿复现（修改前，Node）

| 路径 | 实测 |
| --- | --- |
| 第一段低威胁，前锋破甲、护卫开火击沉 `e0-0` | 剩余 `e0-1` 的序号被误当成 `0`，校验、续档、下一次行动均失败。 |
| 种子 `1`、第一段高威胁，每轮给前锋开屏障后结算 | 第 17 轮船体 `[10,0,0]`，已失联的护卫仍可开火。 |
| 种子 `7`、第一段低威胁，反复屏障/抢修 | 零指令不能结算；全部船体 10 仍能跨过校验上限进入第 61 轮，之后不能操作。 |
| 原种子 `270773197`，原 UI 显示 `1023ABCD` | 把显示文本用于重开得到 `3605093083`，不是原种子。 |
| 无本地存储时开局 | `startSession` 返回失败，但已在内存创建路线状态；UI 把保存失败误作开局失败。 |

## 实现

- 战斗规则位于 `src/ember-convoy.js`：存档状态包括所有选择与按步执行的决策序列，敌舰 ID/序号跨击毁过滤保持稳定。意图目标由种子、航段、回合和 ID 决定；实际受击与 `forecast` 共用 `volley`，计算屏障、护盾、穿透热量和本轮目标失联后的顺延。
- 一轮两个命令，三舰各限一次行动；击毁当前目标即取消它的当轮预告，过载、护卫屏障、每点废料抢修与全舰散热互相竞争。空命令仍可结束回合；12 轮是显式软锁/封锁失败边界。敌群清空立即结束战斗，不免费维护。
- 一段一航路 / 战斗 / 二选一打捞 / 至多一项改装；失联舰不能行动、支援或复活。第三段包含王冠精英，胜利只在用户确认撤离后成立。维修和改装只恢复存活舰。
- 显示种子使用 `EC-XXXXXXXX`，输入可无损还原整数，不会把展示串再次当新文本哈希。决策日志可确定性重演。
- 本地键 `xxsxEmberConvoyV1` 及同名前缀的 pending / backup / rejected 文件均为新档案。schema v2 的严格字段验证、结构校验和 checksum 之外，还要从种子重演整段历史并逐字段匹配；过滤敌人不能再错误地把序号重新编号。保存中断优先恢复更高修订有效事务，其他游戏键不访问；通过写入前检查主档及 pending/backup 字节识别已观察到的并发修改，但 `localStorage` 并非跨标签页原子锁，不宣称解决同一毫秒的并行写竞态。没有可用存储时仍可游玩，但刷新不保存。
- 独立页面 `games/ember-convoy.html` 与 icon 不依赖游戏大厅、旧档案、网络服务或游戏客户端。动态文案经 HTML 转义、没有运行时随机数；入口保留返回总站链接。CSS 定义320px下限、窄屏改列、48px主要触控操作、键盘焦点和 reduced-motion 覆盖。

## 已验证（源码）

`node tests/ember-convoy.cjs` 以实际合法指令走完三段必胜路径及自然决策失败路径；覆盖护盾 / 抢修 / 热量 / 预告 / 精英、目标击毁后存档、目标失联顺延、失联舰不能行动、有限回合软锁、可重演种子、伪造结果拒绝、损坏与 pending 隔离、故障恢复、存档冲突、无存储游玩和挂载 DOM 中经真实可见按钮及键盘的完整胜利。

该定向检查不打开浏览器、GUI 或客户端；没有实测实际浏览器触控、320px 排版截图、屏幕阅读器或跨浏览器 localStorage 事务竞态，也未运行全仓构建/测试。构建列表、站点目录和资源清单由集成阶段单独接线，本模块阶段不改 `content/games.json`、`scripts/published-assets.json` 或 `dist/`。
