# Neon Drift v33：构筑 2.0 与跨模式闭环计划

日期：2026-09-22

## 目标

把当前已经具备内容站点、主线远征和三个短局的 Neon Drift，推进到一条可重复、可理解、能产生构筑差异的完整循环：

`任务 / 短局 → 解锁蓝图 → 构筑实验 → 星图取舍 → 战斗掉落 → 融合分支 → Boss → 奖励与日志`

本轮不以继续增加页面数量为目标，优先解决“掉落选择缺少意义、各模式只共享资源、手机操作密度高、状态边界容易回归”四个限制长期游玩的核心问题。

## 当前基线

- v32 已公开部署，保留舰桥、远征、星图、机库、构筑实验台、图鉴、攻略、公告浮窗、信号中继、回声实验室、深空打捞和本机日志。
- 当前已有五个装备槽：主武器、副武器、核心、战术、推进；主武器掉落已降频，重复装备可自动融合，两个副武器已有独立弹道。
- 当前主要风险不是入口不足，而是构筑分支有限：主武器只有单槽线性成长，副武器种类少，组合主要由固定数值和少量联动组成。
- 当前存档仍是浏览器本机 `localStorage`；真实 Android / iOS / Safari 和物理触控设备尚未验证。

## 本轮实现范围

### P0-A：构筑身份

1. 为装备加入可读的构筑标签与分支信息，标签至少覆盖电磁、穿透、散射、导弹、无人机、护盾、控制等行为。
2. 重复装备继续自动合并；主武器达到上限后不再只增加稀有度，改为允许选择行为分支。
3. 主武器保持单槽，避免立刻把移动端 HUD 和数值平衡扩大成双主炮问题。
4. 扩充副武器行为，使副武器不只是主武器的附属伤害，而是改变目标选择、范围、控制或资源节奏。
5. 掉落卡明确显示“替换 / 融合 / 进入背包 / 触发联动”的实际结果。

### P0-B：跨模式解锁

- 信号中继、回声实验室、深空打捞和远征结束时，除通用资源外，至少有一种可被主战斗直接使用的蓝图、组件或战术解锁。
- 构筑实验台、机库预设、掉落池和图鉴共享同一份解锁档案。
- 委托不再只提供资源，而是引导玩家尝试尚未拥有的构筑行为。

### P0-C：状态与移动端审计

- 统一检查各模式的 enter / start / pause / resume / finish / exit 边界。
- 奖励发放增加幂等保护，重复点击、重复结算和切换页面不能重复获得资源。
- 存档 schema 版本升级和旧五槽预设迁移必须保留。
- 手机优先重做掉落选择、构筑条、底部操作区和详情面板；目标视口为 320×568、390×844、844×390，常用触控目标约 44px。

## 最小方案与最优方案

### 最小可行方案（本轮推荐）

- 仍使用现有原生 JS 和本机存档。
- 增加构筑标签、主武器分支、三类以上副武器行为、跨模式蓝图解锁和奖励幂等检查。
- 先不加入登录、云同步、在线排行榜或第二主武器栏。

收益是可以在一次远征中感受到明确的“选什么、为什么选、选完改变了什么”；迁移风险低，旧存档只需补字段。

### 长期最优方案

- 将 `game.js` 按模式运行时、战斗域、掉落域、存档适配器和 UI 渲染拆分。
- 为路线、掉落和蓝图使用独立确定性随机流，支持本地战报复盘。
- 等内容和数值稳定后，再考虑匿名云同步、排行榜和分享战报。

长期方案维护性更好，但不应阻塞本轮可玩性改造。

## 验收标准

- 至少三种构筑行为可以通过前五波和首个 Boss，且不是单纯 DPS 变大。
- 同一张掉落卡在不同构筑中能显示不同价值。
- 主武器重复出现时有融合或分支价值，不会频繁要求无意义替换。
- 三个短局至少各自改变一种主战斗选择，并能在日志、图鉴或实验台中看到结果。
- 所有奖励重复点击只结算一次；离开模式后计时器、动画和事件全部停止。
- 旧四槽存档仍可进入，五槽和新增字段自动补齐。
- 构建、核心测试、回归测试、静态校验通过。
- 浏览器完整走通：舰桥 → 公告 → 航线 → 出击 → 掉落融合 → Boss / 结算 → 短局 → 回到舰桥。
- 完成桌面、320px、390px 和横屏浏览器验收；真实 Android / iOS / Safari 仍单独标记为未验证。

## 实施顺序

1. 先扩展 `catalog.js` / `core.js` 的数据模型和纯计算逻辑。
2. 再改 `game.js` 的掉落、融合、分支、解锁和结算链路。
3. 接入机库、实验台、任务板、图鉴和公告中的可见反馈。
4. 重做移动端关键布局和触控反馈。
5. 补回归测试与浏览器完整流程，确认后再发布。
