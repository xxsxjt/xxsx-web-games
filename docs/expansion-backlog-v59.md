# V59 既有游戏扩展待办

**状态：设计提案，不代表立项、实现、平衡或上线。** 每款只选一个能落回现有玩家循环的小切片。范围和验收描述均为待实现条件，不是当前功能。

## 现状依据与边界

- 《霓虹突围》自由战场在 `src/freefield.js` 使用 3200×2400 世界坐标、自动锁敌和三座补给站。进入补给站 85 单位范围并且附近 125 单位内没有敌人时，需连续积累 5 秒；受敌人干扰时进度回退。占领后一次性获得维修、EMP、电容芯片和废料，`src/game.js` 同时在世界画面与小地图绘出站点。
- 《信号中继》在 `src/relay-defense.js` 已有三张地图、十二波敌群、三种炮塔与 `first` / `strong` / `fast` 三种炮塔目标优先级。`startWave` 生成并保存队列，`tick` 逐步入场和结算；`xxsxRelayDefenseV1` 保存战斗状态。
- 《回声实验室》在 `src/echo-deck.js` 以敌人行动预告驱动玩家分配能量、打牌和结束回合。`endTurn` 实际结算攻击、护盾、污染与失败；每次动作的状态经 `campaign-core.js` 写入 `xxsxEchoDeckV1`。战斗区已有 `role="status"` 的单条消息区域。
- 以上都是源码行为依据，不是浏览器、实体手机或数值平衡结论。只读回归在本轮规划前已通过：`node tests/freefield.cjs`、`node tests/campaign-games.cjs`、`node tests/regression.cjs`。待办验收须在实现后另行执行，不能用这些基线结果代替。

## 三个小切片

### 1. 霓虹突围：让补给站争夺原因一眼可读

**玩家回路。** 玩家在自由战场移动、自动攻击并决定是否离开火力交战去争夺站点。目前站点圆环能显示进度，但受到敌人干扰时，玩家只能从充能倒退推断原因。

**切片内容。** 新增只读的站点状态判断，并让世界坐标站点及小地图标记共用它：已占领；未占领且玩家距站点至少 85 单位（不在范围）；在 85 单位内且有敌人在站点 125 单位内（受干扰）；在范围内且无上述敌人（正在充能）。玩家不在范围时优先显示“未进入范围”，避免把无法占领误报成争夺。状态函数不改 `charge` / `claimed`；进度环继续表示现有充能，不新增占领规则。判断不得依赖屏幕像素尺寸或摄像机坐标。

**存档兼容。** 站点对象仍只属于当前运行中的战斗状态，不新增续战档、profile 字段或 localStorage 键；不改 `neonDriftProfileV1`、旧短局记录或共享奖励。新开局和 `resetRun` 后三站必须重新初始化为未占领。

**手机约束。** 不增加常驻按钮或摇杆；小地图状态标记与文字需能在 320×568 CSS px 视口辨认。主画面提示避免遮住飞船、敌人或操作区；不依赖悬停，颜色之外还须有可读文字或形状区分。

**可复现验收。**

1. 在 `tests/freefield.cjs` 用固定坐标构造一座站：玩家在范围内、敌人不在 125 单位内，状态为“正在充能”，按固定 `dt` 累积到 5 秒后只占领一次。
2. 将敌人放在站点 124 单位处、玩家保持在占领范围内，断言状态为“敌人干扰”，进度按当前规则以 `dt * 0.35` 回退；把敌人移至 126 单位后再断言恢复充能，剩余进度不被额外重置。
3. 构造不在范围、充能、干扰、已占领四种状态并核对世界画面与小地图状态一致；重复调用绘制/状态读取不得改变 `charge` 或 `claimed`。
4. 实现后重跑 `node tests/freefield.cjs` 与 `node tests/regression.cjs`。这只证明模型和回归夹具；320×568、390×844 的实际排版仍需另做浏览器或设备检查。

**不做范围。** 不新增干扰敌种、站点血量、二次占领、额外经济奖励、随机站点、跨波状态或局外成长；不改自由战场坐标、镜头、生成和自动瞄准。

### 2. 回声实验室：结束回合后给出结算回执

**玩家回路。** 玩家先读敌人意图，再用有限能量打牌，最后结束回合。实际结算可能包含多名敌人的连续攻击、护盾吸收和污染；当前主要依赖生命/护盾数字与通用状态消息，失败时很难从一条消息复盘本轮损失来源。

**切片内容。** 每次 `endTurn` 在既有状态消息中生成一条短回执，至少区分敌人攻击的已挡/未挡伤害、污染结算及最终生命变化；同一轮有多名敌人时按执行顺序呈现，可截短文字但不得把生命损失说成已挡。失败消息保留失败原因并包含本轮摘要。回执来自实际执行结果，不是另写一套预测逻辑。

**存档兼容。** 不增加战斗状态字段、不改卡牌区、节点顺序、存档键或 `schema`；复用现有 `message` 字段并保持不超过 `valid` 的 500 字符上限。V53 缺少 `reserve` 的旧进行中档仍须可恢复；回执只是普通状态消息，刷新后允许显示最近一条，不承诺保留历史日志。

**手机约束。** 复用已有 `campaignLog[role=status]`，不新增弹窗、横向滚动或第二条操作区。消息须换行、可读且不挤掉结束回合/蓄能操作；不以颜色单独区分护盾与生命。

**可复现验收。**

1. 在 `tests/campaign-games.cjs` 固定 `D.create(seed)` 后进入战斗，构造一名 `shooter` 与一名 `drone`，设置可预知的护盾、生命和污染；执行真实 `D.endTurn(s)`，分别断言回执中的攻击者、格挡量、实际生命变化和污染结算与前后状态差值相符。
2. 再用零护盾且生命不足的固定状态触发失败，断言仍显示失败，并且回执中的未挡伤害与生命降幅一致；所有路径结束后断言 `D.valid(s) === true`。
3. 删除旧状态的 `reserve` 字段、保留合法的旧 `message`，断言 `D.valid` 仍接受并能继续一个回合；回执长度不得超过 500 字符。
4. 实现后重跑 `node tests/campaign-games.cjs`。窄屏实际换行、卡牌操作区是否仍可见，另在 320×568 与 390×844 视口检查；模拟 DOM 测试不算实机通过。

**不做范围。** 不改敌人行动、伤害、蓄能、牌组、预估算法或战斗难度；不保存多回合战斗日志，不增加卡牌、敌人、节点或永久属性。

### 3. 信号中继：增加“优先处理护盾”目标模式

**玩家回路。** 玩家按波次构建、暂停调整并用干扰脉冲处理全场护盾。塔已有三种目标优先级，但没有只针对带盾信号的选项；玩家只能更换炮塔或花费电容处理护盾。

**切片内容。** 增加 `shield` 目标模式：有带盾且在射程内的目标时先选带盾目标；同组按“最接近核心”排序，排序完全相同时按敌人 ID 确定次序。若射程内没有带盾目标，回退到最接近核心的可攻击目标。把新模式纳入既有炮塔优先级按钮循环，并在按钮文案/炮位说明中解释含义；不改变炮塔攻击、护盾吸收或敌人路径。

**存档兼容。** 保持 `xxsxRelayDefenseV1` 和状态版本 `version: 1`。现有 `first`、`strong`、`fast` 值继续有效且含义不变；只允许新版本写入 `shield`。无新字段，不迁移或清理旧档。需要明确：运行新版本后保存了 `shield` 的进行中战局，不保证可由仍只认识旧枚举的旧代码继续读取；这不是旧存档兼容的替代测试。

**手机约束。** 复用现有炮位控制按钮（最小触控高度沿用站点样式的 44px），不要求点击 Canvas 上的小敌人；状态文字必须能在窄屏换行，且不能只用颜色显示优先级。

**可复现验收。**

1. 在 `tests/campaign-games.cjs` 创建同一线路上的带盾与无盾敌人，令两者均在测试塔射程内且无盾者更接近核心；切到 `shield` 后执行一轮 `R.tick`，断言炮塔选择并命中带盾者。
2. 令射程内不再有带盾敌人，断言 `shield` 模式改选最接近核心的目标；固定同进度并列条件并反转敌人数组顺序，断言按敌人 ID 选择结果不变。
3. 分别加载含 `first`、`strong`、`fast` 的旧状态并断言 `R.valid` 为真；循环优先级可经过全部四种模式后回到起点，且 `R.valid` 接受新值。
4. 实现后重跑 `node tests/campaign-games.cjs`，并保留三张地图十二波既有合法通关夹具。手机按钮触达与文字布局仍需独立视口检查。

**不做范围。** 不新增炮塔或敌种，不改敌人队列、路径、波次、升级/经济、电容效果、地图、评分和存档版本；不把目标模式扩展成可配置过滤器。

## 推荐顺序与并行边界

| 顺序 | 切片 | 理由 | 主要改动面 |
| --- | --- | --- | --- |
| 1 | 霓虹突围补给站状态 | 只呈现既有争夺状态，不变更奖励与存档，最容易用固定坐标验证。 | `src/freefield.js`、`src/game.js`；新增/拆分的自由战场测试夹具。 |
| 2 | 回声实验室回合回执 | 复用现有结算和消息字段，不增加规则或持久状态，可直接对照状态差值。 | `src/echo-deck.js`、卡牌战斗测试夹具。 |
| 3 | 信号中继护盾优先级 | 是明确的新战术选项，但会改变目标选择结果，需验证回退顺序及既有波次策略。 | `src/relay-defense.js`、塔防目标测试夹具。 |

三项分别触及不同的玩法模型，源码工作可分开；**若三项并行，不应同时编辑** `tests/campaign-games.cjs`、`src/campaign-games.css`、`play.html`、`src/play-loader.js`、`src/campaign-core.js` 或 `scripts/build.mjs`。优先为回声和塔防各自新增独立测试文件，再由集成者统一运行既有回归并审阅共享文件。霓虹的 `src/game.js` 改动只限状态展示，避免与射击、波次和结算改动混在一起。
